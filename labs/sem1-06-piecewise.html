Move the Join

One function can follow different rules in different places. The boundary decides where the handoff happens.

The idea

A piecewise function asks a question before it calculates: which rule owns this x?

Here the first rule is y = x + 2 when x is less than the boundary. At the boundary and after it, the rule is y = 2x.

The two rules do not agree at the starting boundary. The first would reach 3, but the function switches and returns 2. That jump is not a drawing glitch — it is what the rule says.

The code draws each side separately so the gap stays visible. Change boundary and the handoff moves.

Challenges

  1. Change boundary from 1 to 3. The join moves, and the jump changes size because both formulas are being checked at a new x.
  2. Set boundary = 2. Both rules give 4 there. The two pieces touch, so the function is continuous even though its rule still changes.
  3. Change x < boundary to x <= boundary in both places it appears. Which rule now owns the boundary?
  4. Change the right rule from 2 * x to x + 2. There is still a boundary in the code, but can the graph reveal it?
  5. Make the first piece flat: change x + 2 to 3 in the function and in leftValue.
If you know Python

The decision is the same in both languages. JavaScript writes if (x < boundary) { return x + 2; }; Python writes if x < boundary: return x + 2.

JavaScript's NaN means “not a number.” Returning it here tells the plotter that this piece does not own that x. Python can make the same value with float("nan").
