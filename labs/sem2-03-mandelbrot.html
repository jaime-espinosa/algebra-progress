The Quadratic That Eats Itself

The Mandelbrot set is not a new kind of maths. It is the quadratic you are already studying, fed its own answer, over and over.

The idea

Solving a quadratic asks one question once: for which x is x² + c equal to zero?

This asks a different question about the same expression. Start at z = 0, work out z² + c, then put that answer back in as the new z, and keep going:

z → z² + c

z₀ = 0, z₁ = c, z₂ = c² + c, z₃ = (c² + c)² + c, …

Some values of c keep z small forever. Others send it racing off to infinity. That is the only question being asked, once per pixel.

The dark region is every c that stayed. Colour is how many steps the runaways survived first.

The trick is that c is allowed to be a complex number, which is a pair of numbers (cx, cy) rather than one. Squaring such a pair follows from the same FOIL expansion you do by hand: (x + y·i)² = x² − y² + 2xy·i, because i² = −1. That is where the two lines in the loop come from.

Underneath the picture, the same rule runs on the ordinary number line, where c is just a number and you can read the values.

Challenges

  1. Change both 60s to 120 — the one in the loop and the one at the end of picture(...). The edge gets finer, because you are asking each point to survive twice as long before you call it a survivor.
  2. Zoom in. Replace the ranges with picture(-0.78, -0.72, 0.08, 0.14, escapeSteps, 120). The shape at the small scale looks like the shape at the large scale. Nobody wrote that in; it falls out of one line of algebra.
  3. In the number-line loop at the bottom, change c to 0.5. Watch z run away. Then try -1.5, then -2, then -2.1. Find roughly where the behaviour flips — then find that spot on the picture.
  4. Change the escape test from <= 4 to <= 100. Almost nothing changes. Once the distance from zero passes 2, squaring makes it grow every single step, so it can never come back — 4 is just 2².
  5. Change the exponent. Replace the two loop lines with the cube rule: const nextX = x ** 3 - 3 * x * y * y + cx; and const nextY = 3 * x * x * y - y ** 3 + cy; Run it. Squaring gives one big bulb; cubing gives two. The exponent decides the symmetry.
  6. Break it on purpose: delete steps += 1 and run. The loop can never finish, and the page stops it and tells you so. Nothing is lost, and your code stays exactly as you left it. Put the line back.
Why JavaScript and not Python

This lab is the reason the choice matters. Drawing 38,400 pixels with up to 60 steps each is a couple of million operations. JavaScript does that in a fraction of a second in the browser you already have open. The same code under an in-browser Python would need a ten-megabyte download first and would then run far slower.

Write it in real Python at home and it will be recognisably the same program: while x*x + y*y <= 4 and steps < 60: instead of while (x * x + y * y <= 4 && steps < 60) {.

&& is Python's and. || is or. steps += 1 is identical in both.

Python also has complex numbers built in, so there you could write z = z*z + c in one line and skip the two-part bookkeeping. JavaScript makes you do it by hand — which is not a bad thing the first time, because those two lines are the algebra.
