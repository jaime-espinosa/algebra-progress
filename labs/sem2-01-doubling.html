The Moment Doubling Wins

Adding six a day beats doubling — for a while. The whole lesson is finding where that stops being true.

The idea

Linear growth adds the same amount each step: y = start + step·x.

Exponential growth multiplies by the same amount each step: y = start · ratex.

Early on the linear one is usually ahead, because a small number doubled is still a small number. It does not stay ahead. There is a crossing point, and after it the gap is never close again.

The code draws both and then hunts for that crossing with a loop instead of a formula.

Challenges

  1. Run it as-is and read the description under the picture. The curve leaves the top of the window almost immediately — the window only goes up to 120 and by day 10 the exponential is past 4000. Change the graph to graph(0, 10, 0, 4500) and look again. Now the linear line is the one you can barely see. Neither window is lying; exponential growth simply does not fit on a page with its own start.
  2. Set rate = 1.1 — ten percent a day. It looks almost flat. Now change the graph to graph(0, 60, 0, 500) and watch it eat the line anyway. Slow exponential growth still wins; it just takes longer.
  3. Set rate = 0.5. Halving is still exponential. Where does the curve go, and does it ever reach zero?
  4. Raise step to 50. Does the crossing day move a lot or a little? Try to predict before you run it.
  5. Change day += 1 to day += 0.25 to find the crossing more precisely, and add say("linear there:", linear(day)); to see how close the two are at that moment.
  6. Plot the gap instead. Add function gap(x) { return exponential(x) - linear(x); } and g.plot(gap, "difference");. Where the gap crosses zero is the same answer the loop found.
Why JavaScript and not Python

An in-browser Python would mean a ten-megabyte download before this page could draw a single line. JavaScript is already running, so it starts instantly and needs no connection.

rate ** x is the same in both languages.

while (condition) { ... } is Python's while condition: — braces instead of indentation.

The safety catch day < 100 in the loop is worth copying into your Python habits too: any loop that searches for something should have a limit, in case the thing it is looking for is not there.
